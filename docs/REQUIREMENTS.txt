MASTER BUILD PROMPT
PROJECT: codematt Relay

You are acting as a Principal Full-Stack Engineer, Senior Product Designer, Security Engineer, Database Architect, QA Engineer, and DevOps Engineer.

Build a production-ready web application called:

codematt Relay

Tagline:
"Send clearly. Reach responsibly."

The application is a modern, simple, compliant communication campaign manager focused initially on WhatsApp Business Platform.

This must NOT be a WhatsApp Web automation tool.

The application must be designed to deploy on Netlify without requiring a traditional VPS or an always-running local computer.

==================================================
1. CORE PRODUCT VISION
==================================================

codematt Relay is a lightweight communication campaign dashboard for sending approved WhatsApp messages to many opted-in contacts in a controlled, auditable, easy-to-understand way.

The product should feel:

- modern
- Gen Z
- minimal
- clean
- fast
- calm
- trustworthy
- professional
- friendly
- extremely easy to learn

Avoid the visual complexity of enterprise CRM software.

The user should understand the application within approximately 30 seconds after login.

The product should optimize for clarity rather than the maximum possible number of features.

Primary use cases:

1. Import contacts from CSV/XLSX.
2. Organize contacts using tags or segments.
3. Maintain consent/opt-in information.
4. Manage approved WhatsApp message templates.
5. Create a campaign.
6. Select recipients.
7. Preview personalized messages.
8. Schedule or launch a campaign.
9. Process sending asynchronously.
10. Monitor sent, delivered, read, failed, skipped, and pending states.
11. Automatically block opted-out or invalid contacts.
12. Review campaign history and analytics.
13. Export reports.
14. Maintain an audit trail.

The first version should focus on campaign management.

Do NOT turn this into:
- a full CRM
- a social media platform
- an email marketing suite
- an AI chatbot platform
- a complicated omnichannel inbox

Those may be future modules.

2. NON-NEGOTIABLE WHATSAPP COMPLIANCE
==================================================

Use ONLY the official WhatsApp Business Platform / Cloud API.

Never implement or install:

- whatsapp-web.js
- Baileys
- Puppeteer WhatsApp automation
- Selenium WhatsApp automation
- WhatsApp Web QR session automation
- browser session hijacking
- unofficial WhatsApp protocol libraries
- phone number scraping
- contact harvesting
- account restriction bypasses
- message limit bypasses
- anti-ban techniques
- number rotation intended to bypass platform enforcement
- mechanisms for unsolicited cold messaging

Do not implement anything intended to evade Meta or WhatsApp policies.

Broadcast recipients must have valid consent.

Every contact must be capable of storing:

- consent status
- consent source
- consent timestamp
- opt-out timestamp

Contacts without valid consent must not be eligible for campaigns.

Contacts that opt out must be blocked from future broadcasts unless they provide new valid consent.

Add a mandatory confirmation before launching a campaign:

"Saya memastikan penerima dalam campaign ini telah memberikan persetujuan untuk menerima pesan."

The user cannot send until this confirmation is checked.

For proactive WhatsApp broadcasts, use templates approved by WhatsApp/Meta when required.

Do not fake template approval.

Do not allow the user to manually mark a rejected Meta template as approved.

Do not claim that a message was delivered or read unless the WhatsApp webhook reported that state.

The application must show a clear difference between:

queued
sent
delivered
read
failed
skipped

Never interpret "sent" as "delivered".

When official platform rules or API behavior conflict with application assumptions, official WhatsApp Business Platform behavior takes precedence.

8. NETLIFY ARCHITECTURE
==================================================

Design the application around:

Browser
    ↓
React Dashboard
    ↓
Netlify Functions
    ↓
Netlify Database
    ↓
Async Workloads
    ↓
WhatsApp Cloud API
    ↓
WhatsApp Webhook
    ↓
Netlify Function
    ↓
Database status updates

A campaign request must NEVER synchronously loop through thousands of contacts from the browser request.

Correct flow:

User presses Send
    ↓
Server validates campaign
    ↓
Campaign status becomes queued
    ↓
Async workload event created
    ↓
Worker processes recipients in safe batches
    ↓
Official WhatsApp API receives requests
    ↓
Webhook updates delivery state

The initial HTTP request must return quickly.

==================================================
9. IMPORTANT ASYNC WORKLOAD RULES
==================================================

Async Workload events must contain small references such as:

campaignId
batchId

Do not send an entire 10,000-contact recipient list inside an event payload.

Retrieve campaign and recipient data from PostgreSQL when processing.

Use database state as the durable source of truth.

Implement:

- retry strategy
- idempotency
- batch processing
- safe concurrency
- pause support
- resume support
- cancellation checks
- rate-limit handling
- error isolation

Retry only errors that can reasonably succeed later, such as:

- HTTP 429
- temporary network errors
- selected 5xx errors

Respect Retry-After where provided.

Do NOT repeatedly retry permanent validation errors.

A failure for one recipient must not necessarily fail an entire campaign.
